# プロダクト要求定義書

## プロダクトビジョンと目的

**DevTask** は、開発者がコードを書く流れを止めることなくタスク管理できる CLI ファーストのツールです。

既存ツール（Todoist, Trello, Asana）はコードの外にあり、開発者は「別のアプリを開く」コストを払い続けています。DevTask は Git・CI・ブランチといった開発コンテキストをリアルタイムに読み取り、今やるべきタスクを自動的に浮上させることで、この断絶を解消します。

---

## ターゲットユーザーと課題・ニーズ

### ターゲットユーザー

**MVP ターゲット（v1）**: 個人開発者・フリーランスエンジニア
- ターミナルを主な作業場とする開発者
- データを自分でコントロールしたい開発者

**将来ターゲット（v2）**: 小規模開発チーム（2〜10名）
- チーム間でタスクを共有・同期したい開発チーム
- ※ v1 はローカル単体動作のみ。チーム機能は v2 以降で設計する

### 課題

| 課題 | 詳細 |
|---|---|
| コンテキストスイッチコスト | タスク管理のたびにブラウザやアプリに切り替える必要がある |
| 静的な優先度 | 手動で設定した優先度は開発状況の変化に追いつかない |
| コードとの断絶 | タスクと実際のブランチ・コミット・PRが紐付いていない |
| TODO散在 | コード内の `// TODO:` コメントとタスク管理が別管理 |
| ベンダーロックイン | データがサービス側にあり、移行・バックアップが困難 |

### ニーズ

- ターミナルから離れずにタスクを操作したい
- 「今何をすべきか」を考えずに済むようにしたい
- タスクとコードの変更履歴を紐付けたい
- データを自分でコントロールしたい

---

## 主要な機能一覧

1. **CLI インターフェース** - キーボードだけで全操作できる直感的なコマンド体系
2. **コンテキスト駆動の優先度スコアリング** - ブランチ・ファイル変更・時間・依存関係からスコアを自動計算
3. **Git 連携** - ブランチ・コミット・PR とタスクを紐付け
4. **TODO コメント同期** - コード内の `// TODO:` を自動検出してタスク化
5. **条件付きスヌーズ** - 「このブランチに戻ったら再通知」などの開発文脈に即した延期
6. **スコア根拠の透明化** - `task why <id>` でスコア計算の理由を表示
7. **ローカルファースト** - データを JSON/Markdown でローカル保存、Git 管理可能
8. **フォーカスセッション** - Pomodoro タイマーと連動し、作業ログを自動記録

---

## 成功の定義

- `task` 一コマンドで「今やるべきタスク」が 3 秒以内に表示される
- タスクの作成・完了がターミナルから離れずに完結する
- `task why` のスコア根拠を見たユーザーが「なるほど」と感じる（ユーザーテスト5人中4人以上が妥当と評価することを目安とする）
- データは人間が直接編集できるプレーンテキスト（JSON）で保存される

## ビジネス要件

- OSS として公開（MIT ライセンス）
- 課金なしでコア機能をすべて利用可能
- 将来的にチーム向け同期機能を有料オプションとして提供する可能性あり

## ユーザーストーリー

| # | ストーリー |
|---|---|
| US-01 | 開発者として、ターミナルからタスクを追加・完了・一覧表示したい |
| US-02 | 開発者として、今いるブランチに関連するタスクを自動的に上位表示してほしい |
| US-03 | 開発者として、タスクのスコアがなぜそうなったか確認したい |
| US-04 | 開発者として、特定ブランチに切り替えたときに関連タスクを通知してほしい（シェルフック設定が前提：`devtask init` で `.zshrc`/`.bashrc` に自動追記） |
| US-05 | 開発者として、コード内の TODO コメントをタスクとして管理したい |
| US-06 | 開発者として、タスクデータをローカルに保存し Git で管理したい |
| US-07 | 開発者として、フォーカスセッション中に触ったファイルを自動記録してほしい |

## 受け入れ条件

- `task add "タスク名"` でタスクが作成できる
- `task` で優先度スコア付きの一覧が表示される
- `task done <id>` でタスクが完了できる
- `task why <id>` でスコアの根拠が確認できる
- データは `~/.devtask/tasks.json` に保存される
- Git リポジトリ内では現在のブランチ情報がスコアに反映される
- Git 管理外のディレクトリで実行してもエラーにならず、Git シグナルなしでスコアが計算される

※ 条件付きスヌーズ（`task snooze --until branch:`）は v2 機能のため MVP の受け入れ条件には含まない

---

## 機能要件

### コア機能（MVP）

- タスクの CRUD（作成・読取・更新・削除）
- 優先度スコアの自動計算と表示
- Git ブランチとの連携（現在のブランチ名をコンテキストとして使用）
- `task why` によるスコア根拠の表示
- ローカルファイルへのデータ永続化

### 拡張機能（v2 以降）

- TODO コメント同期
- 条件付きスヌーズ
- フォーカスセッション
- CI/CD 連携
- チーム同期

---

## 非機能要件

- **パフォーマンス**: タスク数 1,000 件以下の場合、`task` コマンドが 500ms 以内に応答する
- **信頼性**: タスクデータ書き込み前にバックアップを作成し、書き込み失敗時にロールバックできる
- **ポータビリティ**: macOS / Linux で動作する（Windows は対象外）
- **可読性**: タスクデータは人間が直接編集できるフォーマット（JSON）で保存
- **インストール**: `npm install -g devtask` でインストール可能（v1）。将来的に Homebrew / バイナリ配布も検討
